# Lists 양식 만들기 (수동)

대상: GBI팀. 소요 시간: 양식 2개에 약 15분.
준비: `deploy.ps1`이 끝나 사이트, 목록, 홈 페이지가 있어야 한다. 사이트 소유자 계정으로 한다.

> 화면 문구는 2026년 10월 기준 Microsoft Lists 한국어 화면을 기준으로 적었고, 영어 화면 문구를 괄호에 함께 적었다. 메뉴 이름이 다르면 같은 뜻의 메뉴를 찾는다.
> 한/영 병기(`labels.bilingual: true`)면 열 이름이 `프로그램명 / Program name`처럼 보인다. 아래 표는 한국어 부분만 적었다.

---

## 1. 등록 양식 `프로그램 등록`

### 1-1. 양식 만들기

1. 사이트 왼쪽 메뉴 또는 `사이트 콘텐츠`에서 **프로그램 등록부**를 연다.
2. 위쪽 명령 모음에서 **양식 (Forms)** 을 누른다.
   - 보이지 않으면 **+ 새로 만들기 (New)** 옆 화살표 → **양식** 을 찾는다.
   - 그래도 없으면 `docs/verification-log.md`의 "양식 기능" 항목에 기록하고 IT에 Lists 양식 사용 가능 여부를 묻는다.
3. **새 양식 (New form)** 을 누른다. 양식 편집 화면이 열린다.
4. 양식 제목에 `프로그램 등록` 을 입력한다.

### 1-2. 설명 문구

양식 설명(제목 아래 칸)에 아래를 그대로 붙여 넣는다.

```
직접 만든 업무 프로그램을 등록합니다. 한 프로그램에 한 번만 제출해 주세요.
실제 업무 데이터, 계정, 비밀번호, API 키는 적지 않습니다.
답변에 따라 등급이 자동 판정됩니다. (A: 바로 승인, B·C: 담당자 검토)
등록한 내용을 바꾸려면 홈의 '변경 신청하기'를 쓰세요.

Register a program you built. Do not enter real business data, accounts, passwords or API keys.
The risk grade is assigned automatically from your answers.
```

### 1-3. 열 켜고 끄기

양식 편집 화면 오른쪽(또는 각 질문 옆)의 열 목록에서 아래대로 맞춘다. 순서도 이 순서로 맞춘다 (끌어서 옮김).

**켜는 열 (18개)**

| 순서 | 열 | 형식 | 양식에서 필수 | 비고 |
|---|---|---|---|---|
| 1 | 프로그램명 | 한 줄 텍스트 | 예 | |
| 2 | 용도 설명 | 여러 줄 텍스트 | 예 | |
| 3 | 법인 | 선택 | 예 | |
| 4 | 팀 | 한 줄 텍스트 | 예 | |
| 5 | 만든 사람 | 사용자 | 예 | |
| 6 | 책임 팀장 | 사용자 | 예 | |
| 7 | 형태 | 선택 | 예 | |
| 8 | 개발 도구 | 한 줄 텍스트 | 아니오 | |
| 9 | 사용 범위 | 선택 | 예 | 등급에 쓰임 |
| 10 | 사용자 수 | 숫자 | 아니오 | |
| 11 | 내부 업무 데이터 사용 | 예/아니오 | 예 (가능하면) | 등급에 쓰임. 기본값 아니오 |
| 12 | 개인정보·단가·재무 데이터 사용 | 예/아니오 | 예 (가능하면) | 등급에 쓰임. 기본값 아니오 |

| 15 | ERP·MES에 데이터 입력 | 예/아니오 | 예 (가능하면) | 등급에 쓰임. 기본값 아니오 |
| 16 | 실행 위치 | 선택 | 예 | |
| 17 | 코드·파일 위치 | 한 줄 텍스트 | 아니오 | |
| 18 | 월 절감 시간 | 숫자 | 아니오 | |

**끄는 열 (7개)**: 자동 판정 등급, 확정 등급, 상태, 검토자, 검토 의견, 승인일, 다음 점검일

- 필수 여부는 목록 열 설정을 따른다. 예/아니오 열은 SharePoint에서 필수로 지정할 수 없어 기본값 `아니오`가 들어간다. 양식에 "필수 답변" 스위치가 있으면 켠다.
- 끄는 열 중 하나라도 양식에 남아 있으면 제출자가 상태나 등급을 고를 수 있다. 반드시 끈다.
- 사용자 열, 복수 선택 열, 예/아니오 열이 목록에 나오지 않으면 **멈추고** `docs/verification-log.md`의 "양식의 열 지원"에 적은 뒤 GBI팀 담당자와 대안(한 줄 텍스트·단일 선택으로 바꾸기)을 정한다. 열 형식은 스크립트가 바꾸지 않는다.

### 1-4. 저장하고 링크 복사

1. **저장 (Save)** 을 누른다.
2. **양식 보내기 (Send form)** 또는 **링크 복사 (Copy link)** 를 누른다.
3. 응답할 수 있는 사람 설정이 있으면 **조직 내 사용자 (People in my organization)** 로 둔다. 외부 사용자는 대상이 아니다.
4. 링크를 메모장에 붙여 둔다. (예: `https://<tenant>.sharepoint.com/:l:/s/ax-app-center/...`)

### 1-5. 제출 권한 확인 (8장 "양식 제출 권한")

읽기 권한만 있는 계정(방문자 그룹만 해당하는 일반 직원 계정)으로 링크를 열어 제출해 본다.

| 결과 | 할 일 |
|---|---|
| 제출됨, 등록부에 항목이 생김 | 그대로 진행. verification-log 에 "됨" 기록 |
| 권한 오류 | verification-log 에 "안 됨" 기록. `config.json`의 `permissions.visitorsCanSubmit`를 `true`로 바꾸고 `./04-permissions.ps1` 실행. 흐름 F1의 "보호 단계"를 켠다 (`docs/flows/F1-intake.md` 7장) |

같은 계정으로 등록부 항목을 열어 **편집** 이 안 되는지도 본다 (7.2).

## 2. 변경 신청 양식 `변경 신청`

1. **변경 신청** 목록을 열고 1-1과 같이 **양식 → 새 양식**.
2. 제목: `변경 신청`
3. 설명:

```
등록된 프로그램의 정보 변경, 담당자 변경, 등급 재판정, 사용 중단, 폐기를 신청합니다.
등록번호는 등록부의 ID입니다. 카탈로그나 '내 프로그램' 보기에서 확인하세요.
실제 업무 데이터, 계정, 비밀번호, API 키는 적지 않습니다.
```

4. 켜는 열 (4개): 요청 제목, 등록번호, 유형, 변경 내용 — 모두 필수
5. 끄는 열 (3개): 처리 상태, 처리자, 처리 의견
6. 저장하고 링크를 복사한다 (1-4와 같음).

## 3. 홈 버튼 링크 바꾸기

스크립트는 버튼을 자리 표시 링크(`...#TODO-register-form`, `...#TODO-change-form`)로 만들었다.

1. 사이트 홈(`SitePages/AppCenterHome.aspx`)을 연다.
2. 오른쪽 위 **편집 (Edit)** 을 누른다.
3. **프로그램 등록하기** 버튼을 누르고 연필 아이콘(웹 파트 편집)을 누른다.
4. 오른쪽 창의 **링크 (Link)** 칸을 1-4에서 복사한 링크로 바꾼다. 버튼 글자가 비어 있으면 `프로그램 등록하기`를 입력한다.
5. **변경 신청하기** 버튼도 2에서 복사한 링크로 바꾼다.
6. 카탈로그 목록 웹 파트가 `카탈로그` 보기를 보여 주는지 본다. 다른 보기가 보이면 웹 파트 편집 → **보기 (View)** 에서 `카탈로그`를 고른다. 웹 파트가 없으면 **+** → **목록 (List)** 웹 파트를 추가해 `프로그램 등록부` / `카탈로그` 를 고른다.
7. **다시 게시 (Republish)** 를 누른다.
8. 결과를 verification-log 의 "목록 웹 파트", "버튼" 항목에 적는다.

`./99-verify.ps1 -Stage pages`를 다시 돌리면 "아직 자리 표시 링크입니다" 경고가 사라져야 한다.
