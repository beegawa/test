## 2. 매일·매주 할 일

| 언제 | 할 일 | 어디서 |
|---|---|---|
| 승인 요청 메일·Teams 알림이 올 때 | B·C 승인 요청에 응답. 반려할 때는 이유를 의견에 적는다 (전 직원 공개, D8) | Outlook / Teams 승인 |
| 매일 | `검토 대기` 보기 확인. 중복 제출은 상태를 `폐기`로 (삭제하지 않음) | 등록부 › 검토 대기 |
| 변경 신청 알림이 올 때 | 3장 대로 처리 | 변경 신청 |
| 매주 월요일 | F3 "검토 기한 초과" 메일 확인 | 메일 |
| 점검 회신("변경 없음")이 오면 | 해당 항목의 `다음 점검일`을 +12개월로 | 등록부 |

## 3. 변경 신청 처리

1. 알림의 **등록부 항목** 링크로 항목을 연다.
2. 유형별로 등록부를 직접 고친다.

| 유형 | 등록부에서 할 일 |
|---|---|
| 정보 변경 | 해당 열 수정 |
| 담당자 변경 | `만든 사람`, `책임 팀장` 수정 |
| 등급 재판정 | 바뀐 답(사용 범위·데이터·연결 시스템)을 고치면 `자동 판정 등급`이 다시 계산된다. 등급이 올라가면 `상태`를 `검토 중`으로 바꾸고 해당 등급의 승인 절차를 수동으로 진행(또는 사용자에게 새로 등록 요청) |
| 사용 중단 | `상태` = `사용 중단` (카탈로그에서 빠짐) |
| 폐기 | `상태` = `폐기`. 항목은 지우지 않는다 (이력 보존) |

3. 변경 신청 항목의 `처리 상태`(처리 완료/반려), `처리자`, `처리 의견`을 채운다.

> F1은 **새 항목**에만 동작한다. 등록부를 고쳐도 승인 흐름이 다시 돌지 않는다.

## 4. 등급과 상태

- `자동 판정 등급`은 계산 열이다 (수식은 기획서 5.3). 확정 등급은 승인 때 F1이 넣는다. 검토자가 등급을 바꾸려면 `확정 등급`을 직접 고치고 `검토 의견`에 이유를 남긴다.
- 상태: 접수 → 검토 중 → 승인 / 반려 / 보완 요청 → (사용 중단 / 폐기)
- `보완 요청`은 흐름이 쓰지 않는다. 검토자가 메일로 보완을 요청할 때 수동으로 둔다.
- 버전 기록(주 버전 50개)으로 누가 언제 무엇을 바꿨는지 볼 수 있다: 항목 › … › 버전 기록.

## 5. 전수 조사 가져오기

1. `data/survey-template.csv` 양식을 법인에 배포한다. 엑셀에서 열고 **CSV UTF-8**로 저장하게 한다.
   - 선택지는 한국어나 영어로 적는다 (예: `팀 공용` 또는 `Team`).
   - 연결 시스템이 여러 개면 `;`로 잇는다 (예: `ERP;그룹웨어`).
   - 예/아니오: `예`, `아니오` (또는 Y/N).
   - 만든 사람·책임 팀장은 회사 메일 주소.
2. 파일 검사 (연결 없음): `./07-import-survey.ps1 -CsvPath ../data/<파일>.csv -WhatIf`
   오류 행과 예상 등급이 출력된다. 오류는 법인에 돌려보내 고친다.
3. 가져오기: `./07-import-survey.ps1 -CsvPath ../data/<파일>.csv`
   - `프로그램명 + 법인 + 팀`이 같은 항목이 이미 있으면 건너뛴다. 같은 파일을 다시 넣어도 늘지 않는다.
   - 결과는 `logs/import-<시각>.csv`.
4. **주의**: 가져온 항목에도 F1이 돈다. A는 자동 승인, B·C는 승인 요청이 한꺼번에 간다. 수십 건이면 미리 검토자에게 알리거나, 가져오는 동안 F1을 **끄고** 가져온 뒤 상태·등급을 GBI팀이 일괄 정리한 다음 F1을 다시 켠다.

## 6. 스크립트 다시 돌리기

스크립트는 멱등하다. 설정을 바꾼 뒤 다시 돌려도 있는 것은 건너뛰고 다른 것만 맞춘다. 아무것도 지우지 않는다.

| 하고 싶은 것 | 방법 |
|---|---|
| 법인 추가 | `config.json`의 `entities`에 추가 → `./deploy.ps1 -From 2 -To 2` → F1 `Settings`의 `entityContacts`에도 추가 |
| 검토자 추가 | `people.reviewers` 등에 추가 → `./deploy.ps1 -From 4 -To 4` → F1 `Settings`도 갱신 |
| 사람 빼기 | 스크립트는 구성원을 빼지 않는다. 사이트 설정 › 사이트 권한에서 직접 뺀다. F1 `Settings`도 갱신 |
| 선택지 빼기 | 스크립트는 선택지를 지우지 않는다 (경고만). 목록 설정에서 직접 뺀다 |
| 점검 | `./99-verify.ps1` (전체) 또는 `-Stage perms` 등 |

## 7. 테스트에서 운영으로

1. 테스트 사이트에서 기획서 7장 테스트를 모두 마치고 `docs/verification-log.md`를 채운다.
2. 사람이 `config.json`의 `environment`를 `prod`로 바꾼다.
3. `./deploy.ps1 -WhatIf` 로 대상 URL이 `/sites/ax-app-center`인지 확인한다.
4. `./deploy.ps1 -ConfirmProd`
5. `./99-verify.ps1` (운영에서는 `06-seed-test-data.ps1`을 돌리지 않는다. 스크립트도 막는다)
6. 운영 목록에서 양식 2개를 다시 만들고 (`docs/manual-form.md`), 흐름 3개의 사이트 주소·`Settings`를 운영으로 바꾼 복사본을 만든다.
7. 테스트 흐름은 끈다.

## 8. 문제 해결

| 증상 | 확인 |
|---|---|
| 등록했는데 상태가 계속 `접수` | F1 실행 기록. 연결(공용 계정)이 만료됐는지 |
| `자동 판정 등급`이 비어 있음 | 계산 열 대안(선택 열) 사용 중인지 (`99-verify.ps1`이 경고). 그렇다면 F1이 채우는지 |
| 승인 요청이 안 옴 | F1 `Settings`의 메일 주소, 승인 커넥터 라이선스 (verification-log "라이선스") |
| 직원이 양식 제출 시 권한 오류 | `docs/manual-form.md` 1-5 |
| 흐름이 멈춤 | 흐름 소유자가 개인 계정이 아닌지. 공용 계정과 GBI팀 공동 소유 |
